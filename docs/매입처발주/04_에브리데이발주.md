# 04. 에브리데이(이마트) 발주 자동화

문서 버전: v1.0
최종 수정일: 2026-07-08
대상 스크립트: `에브리데이발주.py` v1.3, `발주서생성.py` v2.7(에브리데이 관련 부분),
`캐리어단가이력업로드.py` v1.5(VRF 부분)

---

## 1. 목적

이마트 에브리데이 각 매장이 VRF 시스템에어컨 설치를 위해 보내오는 발주요청서를
읽어서 구글시트 `캐리어_발주원장`에 반영하고, 이후 `발주서생성.py`가 캐리어에
보낼 발주서를 만들 수 있도록 하는 1단계 스크립트다.

캐리어/윈세이/스타리온 발주(`매입처발주.py`)와 달리, 사방넷 발주총괄을 거치지
않고 **매장이 직접 보낸 엑셀 발주요청서를 그대로 읽는다.**

---

## 2. 파일 위치

```
Z:\★풍림전자 사무 자동화\매입처 관리\1단계_발주원장구글시트업로드\에브리데이발주\
  ├── 원본\        ← 발주요청서 넣는 곳
  ├── 완료\YYYYMMDD\  ← 처리된 파일 자동 이동
  ├── 에브리데이발주.py
  └── 에브리데이발주_실행.bat
```

의존 파일 (같은 상위 폴더 `1단계_발주원장구글시트업로드\`에 위치):
```
캐리어_모델단가테이블.xlsx      ← 기존 파일, 절대 안 건드림 (벤더공통/홈쇼핑 채널)
VRF이마트_모델단가테이블.xlsx   ← 신규 파일 (v1.1), VRF 부품 전용
```

인증키·시트ID는 다른 1단계 스크립트와 동일 (`매입처발주.py` 참고).

## 3. 발주요청서 양식

이마트 매장이 보내는 파일. 파일명 규칙: `{점포명}_발주서-YYYYMMDD.xlsx`
(예: `FC용인상하점_발주서-20260708.xlsx`, 점포명과 "발주서" 사이 공백/언더바 둘 다 인식)

| 열 | 컬럼명 | 비고 |
|---|---|---|
| A | 카테고리 | 참고용, 시트에 반영 안 됨 |
| B | 모델명 | 모델코드. 일반 캐리어 모델이 섞여 들어올 때 `-설치비제외` 접미사가 붙기도 함 |
| C | 수량 | |
| D | 원가(설치비제외,부가세제외) | **매장이 직접 채워 보내는 계약단가.** 참조표에 없는 신규 모델일 때 폴백으로 사용 |
| E | 금액 | 원가×수량, 시트에 반영 안 됨(스크립트가 재계산) |
| F | 받는사람 | 실구매자명 |
| G | 우편번호 | |
| H | 주소 | |
| I | 연락처 | 실구매자휴대폰 |
| J | 비고 | 배송 마감일 등 매장 지시사항. 예: `"7월 10일 (금) 오전 중 입고 必"` |

합계 행(모델명이 빈 행)은 자동 제외.

## 4. 단가 결정 로직 (v1.2부터 확정)

**1순위 — VRF이마트_모델단가테이블.xlsx (VRF 부품) / 캐리어_모델단가테이블.xlsx
벤더공통 채널 (`-설치비제외`/`-설치비포함` 접미사 모델)**

- 매달 `캐리어단가이력업로드.py`가 캐리어 운영안에서 자동 갱신하므로, 매장이
  손으로 채워 보내는 원가보다 최신성이 높다고 판단(Dr. Corcan 확정, 2026-07-08)

**2순위 — 발주요청서 자체의 원가 컬럼**

- 참조표에 아직 없는 신규 모델일 때만 대체로 사용

**판정 흐름:**
```
참조단가 있음
  → 그 값 사용
  → 발주요청서 원가와 다르면: 콘솔에 경고, 참조표 값 그대로 사용(자동 진행 안 멈춤)
참조단가 없음 + 발주요청서 원가 있음
  → 발주요청서 원가 사용, "신규 모델 가능성" 로그
참조단가도 발주요청서 원가도 없음
  → 단가없음, 캐리어공급가_VAT제외 빈칸으로 시트 반영, 콘솔에 경고 목록 출력
```

⚠️ **미해결 (2026-07-08 기준):** 단가 불일치가 발생해도 자동으로 계속 진행된다
(경고만 출력, 멈추지 않음). 사람이 콘솔을 보며 직접 실행하는 지금은 괜찮지만,
이 스크립트가 워처에 연결되면 — 불일치 시 `확인이_필요합니다`로 멈추게 할지
결정 필요.

### `-설치비제외` / `-설치비포함` 접미사

일반 캐리어 모델(보통 설치상품으로 취급됨)이 VRF 세트에 딸려서 배송상품으로
나갈 때 붙는다. 예: `EARP-0121GAWSD-설치비제외`.
- 접미사를 떼고 `캐리어_모델단가테이블.xlsx`의 벤더공통 채널에서
  `공급가_설치제외`/`공급가_설치포함` 컬럼으로 조회
- `발주서생성.py`에서 아이템(모델코드) 표시 시 접미사 제거, 대신 할인율(AM열)에
  `"설치비제외"` 표시 (§6 참고)

## 5. 구글시트 `캐리어_발주원장` 반영 — 컬럼 순서 (v1.3, 중요)

`ws.append_rows()`는 **헤더 이름이 아니라 A열부터 위치대로** 값을 쓴다.
아래 순서는 실제 시트 헤더와 왕복 검증(써서 다시 읽기)까지 마친 정확한 순서다.
**이 순서를 절대 추측으로 바꾸지 말 것 — 실제 헤더가 바뀌면 반드시 재확인.**

```
접수일, 구분, 완료여부, 오더번호,
모델코드, 수량, 설치점구분, 설치점코드, 배송구분,
캐리어공급가_VAT제외, 발주금액_VAT포함,
납기요구일, 주문자명, 실구매자명, 실구매자휴대폰, 실구매자전화번호,
실구매자우편번호, 실구매자주소, 물류메시지,
사방넷주문번호, 채널, 설치점주소
```

값 매핑:
```
구분             = '에브리데이'
완료여부         = '신규'
설치점구분       = 점포명 (파일명에서 추출)
배송구분         = '직송' (고정)
주문자명         = '' (에브리데이 발주요청서엔 별도 주문자 정보 없음)
실구매자명       = 받는사람
실구매자휴대폰   = 연락처
실구매자전화번호 = 연락처 (일반전화 정보 없어 휴대폰과 동일값 — 발주서생성.py
                   기존 관례와 동일)
물류메시지       = '[{파일명}] {비고}'  ← 대괄호 태그는 중복 처리 방지용 내부 식별자,
                   지우면 안 됨(아래 §7 참고)
사방넷주문번호   = '' (에브리데이는 사방넷 주문번호 개념 없음)
채널             = '에브리데이'
```

**빈 값으로 남기는 컬럼:** `설치점코드`, `CS여부`, `CS내용`, `설치비_VAT제외`,
`마감단가_VAT제외`, `마감금액_VAT제외`, `마감금액_VAT포함`, `처리구분`, `처리키`,
`주문상태` — `발주서생성.py`도 `캐리어_발주원장_검증.py`도 이 컬럼들을 안 쓰므로
현재는 비워도 문제없음(코드로 확인 완료, §8 참고).

## 6. 2단계(`발주서생성.py`)에서의 에브리데이 특수 처리

`build_carrier_rows()`는 `구분='에브리데이'`인 행을 감지해서 세 갈래
(설치상품/에브리데이/일반배송상품) 중 에브리데이 전용 규칙을 적용한다.

| 항목 | 일반 배송상품 | 에브리데이 |
|---|---|---|
| 행 순서 | 모델코드 알파벳순 정렬 | **발주요청서 원본 순서 그대로** (물류메시지의 `[파일명.xlsx]` 태그로 그룹핑) |
| 비고1(AC열) | `"빠른 출고 " + 물류메시지` | 물류메시지 내용만 (있으면), 없으면 `"빠른 출고"` — `[파일명.xlsx]` 태그는 표시 직전 제거 |
| 비고2(AD열) | 공란 | **설치점구분(매장명)** — 배송상품이라도 표시 (기존 규칙의 예외) |
| 납품요청일 | 발주일+1일 자동계산 | **비고에서 "O월 O일" 패턴을 찾아 그 날짜 우선 사용**, 못 찾으면 자동계산값+콘솔 안내 |
| 할인율(AM열) | 공란 (홈쇼핑 전용 모델만 "미리주문") | `-설치비제외` 접미사 모델만 `"설치비제외"` 표시 |

**행 순서를 유지해야 하는 이유:** VRF 세트는 여러 부품이 한 세트로 묶여서
배송돼야 하고, 매장이 명시한 배송 마감일(예: "반드시 7월 10일까지 배송")이
걸려있는 경우가 많아서, 알파벳순으로 흩어지면 캐리어 창고에서 세트 단위
처리가 어려워진다(2026-07-08 FC용인상하점 실사용 테스트에서 확인).

**검증 방법:** 이경희 실장님이 손으로 만든 "정답 발주서"와 자동 생성 결과를
필드 단위로 전부 대조 — 비고1의 "오전 중" 2글자(원본 텍스트 그대로 옮긴 결과,
정답 쪽 수기 작성 시 누락으로 판단)만 빼고 9행 전부 일치 확인.

## 7. 중복 처리 방지

같은 발주요청서 파일을 다시 넣어도 중복 등록되지 않도록, `물류메시지` 컬럼
앞에 `[파일명.xlsx]` 태그를 붙여서 저장한다. 실행 시작 시 기존
`캐리어_발주원장`의 모든 물류메시지에서 이 태그를 정규식(`\[(.+?\.xlsx)\]`)으로
추출해서 이미 처리된 파일 목록을 만들고, 같은 파일명이 또 들어오면 건너뛴다.

⚠️ **이 태그는 지우면 안 된다.** 사람이 보는 발주서에는 `발주서생성.py`가
표시 직전에만 떼어내고(§6), 시트 원본 데이터에는 그대로 남겨둔다.

## 8. 캐리어_발주원장_검증.py와의 관계

워처의 1단계 검증기(`캐리어_발주원장_검증.py`, v0.1, 아직 워처 체인에 완전
연결 전)가 에브리데이 행과 충돌하지 않는지 코드로 직접 확인함(2026-07-08):

- 처리키 중복/형식 검증 → 처리키가 빈 값이면 자동 스킵
- 주문당 처리구분 중복 검증 → 사방넷주문번호가 빈 값이면 자동 스킵
- 완료여부 정합성 검증 → 처리구분이 빈 값이면 어느 조건에도 안 걸림
- 분할 합계 검증 → 매입처발주.py의 발주총괄 원본과만 대조하므로 에브리데이는
  애초에 대상이 아님

**결론: 지금 구조로는 이 검증기와 에브리데이 데이터가 마주쳐도 안전함.**
단, 실전에서 두 흐름이 같은 워처 실행 안에서 같이 돈 적은 아직 없음.

## 9. 워처 연결 여부

**아직 연결 안 됨.** `풍림_발주자동화_워처.py`는 `매입처발주.py`(캐리어/윈세이/
스타리온용)만 감시하며, `에브리데이발주\원본\` 폴더는 워처의 감시 목록에 없다.

Dr. Corcan 결정(2026-07-08): "일단 수동으로 가자" — 오늘 막 전면 재설계했기
때문에 최소 몇 차례는 사람이 직접 실행하며 지켜보는 게 안전하다는 판단.

**현재 반자동 구조:**
```
와이프님이 에브리데이발주.py만 수동 실행 (구글시트 업로드까지)
  → 이후(발주서생성·오더번호매칭)는 이미 워처가 같은 캐리어_발주원장 시트를
    보고 있어서 자동으로 잡아서 처리함
```

완전 자동화(워처에 4번째 감시 폴더로 추가)는 몇 차례 수동 사이클로 안정성
확인 후 재검토 예정.

우편번호·주소·물류메시지·채널)이 2칸씩 밀려 엉뚱한 컬럼에 들어가던 문제 수정.
실제 헤더 행을 Dr. Corcan이 직접 확인해줘서 정확한 순서로 재구성, 왕복 검증
(써서 헤더 이름으로 다시 읽기)으로 22개 컬럼 전부 일치 확인.
